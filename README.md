# Lenovo ThinkBook G7 ARP (Linux Media Keys Fix)

This repository/document provides a native Linux fix for the broken volume and mute keys on the **Lenovo ThinkBook 14/16 G7 ARP** (and potentially other modern Lenovo laptops).

## The Hardware Bug

Due to how Lenovo programmed the Embedded Controller (EC) on the PS/2 bus (partially to accommodate the new Windows Copilot key behavior), the media keys behave incorrectly on Linux:

1. **Runaway Volume:** The Volume Up/Down keys send rapid hardware repeat codes (`value 2`) but completely fail to send a release code (`value 0`). This causes Linux to think the key is held down forever, blasting the volume to 100% or 0%.
2. **Mute Key Bounce:** The Mute key physically bounces, sending up to 7 complete press/release signals in a single second when pressed just once.

## Part 1: Fix Runaway Volume Keys (hwdb)

Since the hardware forgets to tell the OS when you let go of the volume keys, we can use a `systemd-hwdb` modifier to inject a synthetic release event exactly 9 microseconds after every press.

**1. Create the hardware database rule:**
Open your terminal and create a new file:

```bash
sudo nano /etc/udev/hwdb.d/90-lenovo-media-fix.hwdb
```

**2. Paste the following configuration:**

> [!IMPORTANT]
>  Ensure there is exactly ONE space before the `KEYBOARD_KEY` lines! The `!` is what forces the instant release.

```ini
# Fix missing release events for Lenovo ThinkBook G7 ARP
evdev:atkbd:dmi:*
 KEYBOARD_KEY_ae=!volumedown
 KEYBOARD_KEY_b0=!volumeup
```

**3. Apply the changes:**
Update the hardware database and trigger the new rules:

```bash
sudo systemd-hwdb update
sudo udevadm trigger
```

_Your volume keys will now behave normally and stop repeating the exact millisecond you lift your finger._

## Part 2: Fix Mute Key Bounce (User-space script)

Because `systemd-hwdb` operates on logic rather than time, it cannot natively debounce a keyboard key. Furthermore, Wayland input drivers (`libinput`) intentionally do not debounce keyboard keys.

To filter out the 6 "ghost" presses generated by the hardware bounce without burning CPU cycles, use `flock` to create a lightweight, 200ms user-space debounce filter.

**1. Update your Window Manager/Desktop Environment config:**
Bind your Audio Mute key (`XF86AudioMute`) to the following command instead of the standard toggle:

```bash
flock -n /tmp/micmute-$UID.lock -c "wpctl set-mute @DEFAULT_AUDIO_SOURCE@ toggle && sleep 0.2; rm -f /tmp/micmute-$UID.lock"
```

### How the Mute script works:

- `flock -n` tries to create a lock file.
- On the very first hardware signal, it succeeds, toggles the mute state via Wireplumber (`wpctl`), and goes to sleep for 0.2 seconds.
- When the hardware sends the remaining 6 broken bounce signals a few milliseconds later, `flock` sees the lock file is still active and instantly drops the ghost inputs with zero CPU overhead.
- After 0.2 seconds, the lock is removed, ready for your next intentional press.
